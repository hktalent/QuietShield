# QuietShield 样本回放失真分析（v4.0，2026-11-19）

> 分析对象：`logs/audio/` 下已落盘的真实样本（最新 11-19，最早 11-05），共抽样 80 个文件做统计，另对 6 个代表文件做逐样本解剖。
> 分析工具：ffmpeg 解码 → PCM float → numpy/scipy 计算（脚本 `audio_health_probe.py`）。
> 结论全部来自实测数值，不是原理推演。

---

## 一、结论：四个缺陷叠加，按影响排序

| # | 缺陷 | 客观证据 | 听感后果 |
|---|---|---|---|
| 1 | **120Hz 高通把低频主体切除** | 40Hz −19.1dB / 60Hz −12.3dB / 80Hz −7.8dB（滤波器实测响应）；真实样本 40–80Hz 相对 160–240Hz **中位亏欠 −25.0dB**，而同一批走"原始轨"回退路径的样本只亏 −8.2dB（差 17dB） | 震楼器的"闷响/震"消失，只剩中高频"啪嗒"，与现场差别最大的一条 |
| 2 | **前置增益 ×3 把响事件推过满量程** | 抽样 80 个文件中 **5 个（6%）峰值 >1.0**，最高 1.95（该文件 0.43% 样本超满量程）；压缩器模拟：输入峰 1.5 时只压 4.1dB，输出仍 1.38 | 撞击瞬间破音、爆点 |
| 3 | **右声道是数字静音** | 抽样 80 个文件中 **38 个（48%）R 声道 RMS = −167dB（全零）**，L 才有信号 | 立体声容器一半空轨；任何单声道/降混播放器音量直接 **−6dB**，部分播放器只有左声道出声 |
| 4 | **电平两端失控、与记录 dB 脱钩** | 抽样中 11% 样本峰值 < −30dBFS（最低 −29.8dBFS）；DB 报 39.9–61.4 dB 对应文件峰 −26.8 ~ −3.8 dBFS，散差 ±6dB | 看着"48.6dB"的记录，听到的是几乎无声的样本；把音量拉满就听到本底噪声 |

### 1.1 关键：dB 与样本不是同一条信号
- 检测：`analyser` 直接接 `src`（**未经处理**）→ 显示的分贝、入库的 `peak`
- 样本：`src → gain(3) → highpass(120) → compressor(-10/10) → MediaStreamDestination → MediaRecorder`
- 两者之间差一条增益+滤波+压缩链，因此"记录强度"与"回放响度"天然不可比，且样本被链改形。

## 二、已排除的假设（诚实标注）

| 假设 | 实测 | 判定 |
|---|---|---|
| 多重 Opus 重编码造成代际损失 | 原始 240k → 96k → 96k → 96k 三代：各频带变化 **<0.2dB**，峰值/波峰因数不变 | **不是主因** |
| 服务端 5× 放大 + `alimiter(0.95)` 造成失真 | `logs/settings.json` 自 11-07 起 `audioBoost5x:false`，这 80 个样本均未经 5× | **当前未生效** |
| 压缩器把整体背景抬起来/压扁 | 安静段输入峰 0.15–0.6 时压缩器衰减 0dB（阈值 −10dB 未触发） | **只在响事件上局部起作用**，非整体变闷原因 |
| 播放器侧额外增益 | `js/player.js` 无增益节点，仅频谱可视化 | 不参与 |

## 三、与上次被回滚的 PR #1 的关系

PR #1（`8f97eb5 Fix noise sample playback distortion`）的改动 = 删客户端 `sampleDest` 放大链 + 服务端 `-c:a copy` + 默认关 5×。

- 与本次测量**方向一致**的部分：去掉前置增益/高通/压缩（正是缺陷 1、2 的来源）。
- 与本次测量**无证据支持**的部分：服务端 `-c:a copy`（实测重编码损失 <0.2dB，收益接近 0）、默认关 5×（该设置已是 false）。
- 该 PR 被 `672e96b` 整条 revert，原因未查明（trace 无记录）。本次不再整条照搬，只按实测证据取最小改动。

## 四、修复建议（按证据，最小改动、可逐条回滚）

1. **样本录音改回原始音轨**：`MediaRecorder` 直接用 `at`（麦克风原始 track），或把 `SAMPLE_GAIN=1`、`SAMPLE_HP_FREQ` 关闭。
   - 理由：缺陷 1（−17~−25dB 低频）与缺陷 2（6% 削波）都由这条链产生。
   - 想"听得清"靠播放侧增益（页面已有 5× 播放），落盘保持原始动态 —— 这也是取证文件该有的形态。
2. **强制单声道 / 补右声道**：录制前检查 `sampleDest.stream` 的第二声道，若全零则改用 `numberOfChannels:1` 或复制 L。
   - 理由：48% 样本右声道空，白扔一半码率并让降混播放器掉 6dB。
3. **峰值保护只在服务端做一次**：需要限幅时用 `-af alimiter=limit=0.95:level=0` 单独一步，客户端不做前置增益。
   - 理由：客户端 limiter 实测在 1.5 峰值时只压 4.1dB，等于没保护。
4. **入库 peak 语义澄清**：`peak` 是 SPL 估计（analyser 原始链），不是文件电平；建议同时写 `file_peak_dbfs`，页面显示"回放电平"。
   - 理由：两者散差 ±6dB，用户按 dB 期待音量必然落空。
5. **验收指标**（修复后抽 30 个新样本）：
   - 右声道空 = 0
   - 峰值 >1.0 = 0
   - 40–80Hz 相对 160–240Hz 亏欠中位 ≥ −10dB（即恢复低频）
   - 文件峰值 ≥ −20dBFS（不再出现近乎无声的样本）
