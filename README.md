# QuietShield

住宅环境「噪声检测 + 前置摄像头录像」采集系统，纯浏览器运行，后端 Python 实时落盘。
反制震楼器相关技术：**记录、监控、取证**，以及如下两套定位/阻断手段。

| 手段 | 作用 | 文档 |
|---|---|---|
| 手机磁力计定位 | 贴着楼板找强磁峰值（>300 μT），设备拆移后回落 <60 μT，用于**确认哪块楼板是振动源** | [docs/detection.md](docs/detection.md) |
| Kali Wi-Fi 识别与阻断 | 识别对方 Wi-Fi 的 SSID / BSSID，把该 AP 下所有客户端打下线，**切断联网型/远程可控震楼器的控制链路** | [docs/interception.md](docs/interception.md) |
| ⚠️ EMP 穿透干扰 | **无效且极度危险**：物理上无法定向穿透楼板，会烧毁整层楼电子设备，涉嫌犯罪，**绝对禁止尝试** | [docs/emp-warning.md](docs/emp-warning.md)（警告） |

## 功能

- **噪声检测**（保留）：实时 dB、波形、超标事件日志（本地 + 后台 `/api/log`），按《噪声污染防治法》昼夜阈值（昼 55 / 夜 45 dB）。
- **前置摄像头录像**（新增）：网页 `getUserMedia` 拉取前置摄像头，`MediaRecorder` **分段独立录制**（每 30 秒 `stop()` 产出一段**完整可播**的 WebM），**实时分片上传**后台，断网最多丢一段；会话结束时后端用 ffmpeg 把本会话分片合并成**每 10 分钟一段的 MP4**。
- **设备指纹**：Canvas + WebGL + UA 等特征 SHA-256，作为每台设备的唯一标识（存 localStorage，跨刷新稳定）。
- **标签**：录像前可在界面输入标签（如"客厅""卧室"），标签作为录像文件名与噪声日志的组成。
- **文件名**：每段视频文件名为 `{标签}_{会话开始}_{本段开始}_{本段结束}_seg{序号}.webm`，时间均为 `YYYYMMDD_HHMMSS`（年月日时分秒），**始终含开始与结束标志**；会话结束合并为 `{标签}_{会话开始}_{会话结束}_第N段.mp4`。
- **多设备隔离**：后台按 `videos/<设备指纹>/` 建目录落盘，不同设备写入不同文件，互不冲突；同设备分片文件名带会话+序号，天然有序。
- **录像回看**：`/review.html` 按设备/标签/会话列出录像，**优先播放合并后的 10 分钟 MP4**，无 MP4 时回退到各分片。
- **布局**：主页「声压级」卡与「前置摄像头录像」区**同一行各占 50%**；声压计画布撑满卡片、dB 数字用视口单位随界面放大等比例缩放（不写死，自适应）。
- **单按钮启动**：点「开始监测」同时启动噪声监测与视频录制，停止一并停止；无独立「开始录像」按钮。
- **噪声样本回放**：界面「噪声事件日志」每行含**噪声录音播放 + 🔊×5 放大播放**（超标时自动录样本，未录则显示"—"）。
- **标签自动记忆**：录像标签输入后存浏览器 localStorage，同客户端下次打开自动回填，无需重输。
- **噪声日志来源标识**：`logs/noise_log_YYYY-MM-DD_<标签>.html` 的「设备ID」列改为「录像标签」，显示标签内容、不再显示设备指纹哈希。
- **单条删除日志**：前端日志表每条记录有红色「删除」按钮，删除时**同步删除前端**（日志列表 + IndexedDB 音频）**并调用后端 `/api/log/del` 删除对应日志行**（按触发时间戳唯一 id 匹配，遍历当日所有标签/凌晨日志）。
- **清空日志仅限前端**：「清空日志」只清空前端列表与 IndexedDB，**不影响后端日志文件**。
- **日志分卷**：后台日志单文件超过 100MB 自动滚动为 `当前文件名_01 … _0N`，每个文件 ≤ 100MB。
- **按标签独立日志**：每个标签每天一个独立 HTML `noise_log_{日期}_{标签}.html`；记录仍共用同一个 SQLite 数据库（JSON 数据），页面按标签过滤显示与分页。
- **凌晨独立日志**：01:00~06:00 的记录按标签额外单独存一份 `noise_log_{日期}_{标签}_凌晨0100-0600.html`。
- **录音保存音量×5**：默认关闭，以保留录音原始动态；可在主界面开启，将录音放大 5 倍并峰值限幅（0.95）后**直接覆盖原文件**，设置持久化在 `logs/settings.json`。此设置与播放时的「5倍音量播放」独立。

## 触发 / 结束规则

按时段区分（`thr`：白天 06:00~22:00 为 55dB，夜间 22:00~01:00 与凌晨为 45dB）：

| 时段 | 触发条件 | 结束条件 |
|---|---|---|
| 凌晨 01:00~06:00 前 | `噪声>45dB` **或** `噪声>背景+6dB`（任一） | 降到 `背景+3dB` 以下并持续 3s |
| 白天 06:00~22:00 | 仅 `噪声>55dB`（不用背景） | 降到 `50dB` 以下并持续 3s（触发线-5dB 滞回） |
| 夜间其他 22:00~01:00 | 仅 `噪声>45dB` | 降到 `40dB` 以下并持续 3s（触发线-5dB 滞回） |

> 触发需连续超线 **0.3 秒**（`TRIG_HOLD_SEC`）才开记，单次采样毛刺不落盘；结束后需连续安静 **3 秒**（`MERGE_GAP_SEC`）才关闭本次记录，窗口内再次超线视为同一次噪声继续累加（起点回填到首次超线时刻，时长按「首次超线 → 首次回落」计算），因此连续起伏的噪声不会再被切成多条不到 2 秒的碎片记录。

> 背景噪声（`noiseFloorDb`）只服务于**凌晨**的「背景+6dB」触发判断：启动自校准（白天取前 2 秒**平均值**、凌晨取前 10 秒**中位数**作初始背景）→ 之后仅对**安静样本**（低于背景+3dB）做指数滑动平均持续跟踪 → 事件结束进入 5 秒冷却（期内不更新背景，防刚停噪声拉高背景）。单条噪声会话最长记录 **60 秒**（`MAX_SESSION_SEC=60`），超时切段重记。

### 噪声样本缓冲（长跑稳定性关键）

样本录音走「环形常驻 + 事件截取」：MediaRecorder 直接读取麦克风音轨，不额外施加增益、滤波或压缩；服务端默认只重封装/裁剪容器，不重复有损编码（仅显式开启「保存音量×5」时才做增益限幅编码）；平时每 10 秒重建一个**带文件头**的录音段（保证片段从头可播），触发时取当前整段（≈ 触发前 ≤10 秒 + 事件 ≤60 秒）。

| 常量 | 值 | 作用 |
|---|---|---|
| `RING_RESTART_MS` | 10000 | 空闲时切段间隔，触发前上下文最多约 10 秒 |
| `RING_MAX_MS` | 90000 | 单段时长硬上限，到点先落盘再切段 |
| `RING_MAX_BYTES` | 8 MB | 单段字节硬上限，超限丢弃后续分片 |
| `MAX_AUDIO_DATAURL`（服务端） | 16 MB | 拒绝异常大的 dataURL 落盘 |

> 历史故障：旧实现「事件期间永不切段」且关闭流程在 `await` 之后才复位状态，
> 持续噪声（震楼器整夜运转）时同一段会被反复关闭、反复做 base64，
> 缓冲一路涨到 62MB（`logs/audio/` 里可见多个 60MB+ 的 webm），Safari 主线程被堵死 → 浏览器卡死。
> 现在单条样本稳定在 1MB 量级。

## 录像同时采噪声：为什么不冲突

浏览器中**一次** `getUserMedia({video, audio})` 拿到「音视频合并流」。同一路音频轨道可被**两个消费者并行读取**：

- `AudioContext.createMediaStreamSource()` → `AnalyserNode` → 实时噪声 dB 检测
- `MediaRecorder` → 录像（含声音）

合并流下双读不冲突。真正会冲突的是**两次分开的 getUserMedia**（一次纯音频、一次纯视频），在 iOS Safari 等移动端会因权限/流仲裁打架。本项目因此强制走合并流，噪声检测与录像可同时进行，无需降级。

> 已移除原「磁场」「振动」的**页面内**监测、记录、日志功能及对应 UI/列。磁场定位改为手机 App 人工巡检流程，见 [docs/detection.md](docs/detection.md)。

## 震楼器反制手段

本项目本身只负责「记录 + 取证」。要**定位振动源**和**让远程控制失效**，配合以下两套离线流程，结论再回到本项目的时间轴上与噪声日志、录像合并归档。

### 一、检测：手机磁力计定位楼板振动源

震楼器内部是电磁铁 / 偏心电机，工作时既产生交变磁场，也有铁芯带来的直流偏置磁场。地磁约 25–65 μT，因此：

- 在震楼器所在**楼板位置**，磁力读数通常 **> 300 μT**；
- 震楼器**拆移或断电后**，同一位置读数会**回落到 60 μT 以下**。

这条「装上就高、拆走就低」的强相关性，是判定振动源最直接的证据。操作要点：摘掉磁吸壳 → 测室内基线 → 30–50 cm 网格贴面粗扫 → 10 cm 细化找峰值 → 与噪声 dB 同步比对启停时刻 → 拍照 + 3 次重复读数打包。

完整流程、判读分级表、误判排除见 **[docs/detection.md](docs/detection.md)**。

### 二、检测 + 拦截：Kali 识别 Wi-Fi 并打下线

针对**联网型 / 可远程控制**的震楼器（Wi-Fi 模块、智能插座、4G 网关）：

1. **识别**：Kali 加载支持注入的网卡 → `airmon-ng` 开监听 → `airodump-ng` 扫出对方 **SSID / BSSID / 信道 / 客户端**，用 PWR（-30 ~ -50 dBm 即极近）、出厂默认 SSID（`ESP_xxxx`、`Sonoff`、`Tuya`…）、掉线自动回连等特征锁定目标。
2. **拦截**：`aireplay-ng --deauth`（或 `mdk4` / `bettercap wifi.deauth`）对该 BSSID 发送取消认证帧，**把所有客户端一起打下线**，设备无法连厂商云，远程开机/控制随之失效。
3. **验证**：App 显示离线、airodump 客户端数归零、噪声 dB 与磁场读数同步回落；保留 cap 文件与操作时间线取证。

命令、分级方案（路由器侧 → deauth → evil twin）、802.11w/PMF 与 4G 版本的失效场景见 **[docs/interception.md](docs/interception.md)**。

> 法律边界：仅限自身合法权益受侵害时的紧急止损与取证；擅自干扰他人无线通信涉嫌违法。设备归属不明或走 4G/BLE 时，优先物业 / 公安 / 生态环境部门 / 诉讼途径。

### ⚠️ 无效且危险的方案：EMP 穿透干扰
**绝对禁止尝试**：任何试图用EMP（电磁脉冲）穿透楼板干扰/破坏震楼器的方案，都在物理上无效、法律上违法、安全上致命——EMP是全向发射，会先烧毁你自己和整层楼的所有电子设备（包括医疗设备、电梯控制、消防系统），震楼器反而因为楼板屏蔽和距离远根本不会被打中；且涉嫌「破坏计算机信息系统罪」，最高可判5年以上。完整警告见 [docs/emp-warning.md](docs/emp-warning.md)。

## 后端接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/log` | 噪声超标事件入库（含设备ID、标签） |
| POST | `/api/log/del` | 删除后端某条日志：前端删除按钮触发，body 传 `timeTs`，按 `id=log-{timeTs}` 匹配并从当日所有噪声日志分卷/凌晨文件中删除对应行 |
| POST | `/api/video/upload?deviceId=&tag=&start=&segStart=&segEnd=&segIndex=` | 二进制分片（原始 body），落盘 `videos/<deviceId>/{tag}_{会话开始}_{段开始}_{段结束}_segN.webm` |
| POST | `/api/video/finalize` | 写会话元数据（标签、起止时间） `<...>_meta.json` |
| GET | `/api/videos` | 按设备/标签/会话返回录像清单（含 webm 分片与合并的 mp4） |
| GET | `/videos/<deviceId>/<file>.webm` / `.mp4` | 播放分片或合并后的 MP4（正确 mime，支持中文名） |
